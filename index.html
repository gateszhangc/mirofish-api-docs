Guides

Integrate MiroFish into your backend.

The API exposes the same workflow used by the MiroFish web application: source intake, ontology and graph construction, simulation, and report interaction.

Authentication

Create a key at mirofish.my/api-keys. Store it in a secret manager and send it on every request:

Authorization: Bearer mf_live_...

Keys are shown in full only when created. API responses include X-Request-Id. State-changing calls accept Idempotency-Key; reuse the same value when retrying the same request.

API credits

API credits are prepaid, account-level credits shared by all keys and separate from web subscriptions. The first accepted simulation start costs 100 credits. Project creation checks affordability but does not deduct; reads and report chat are not charged.

1. Upload sources

Calculate each file's SHA-256 before initializing an upload session. PDF, Markdown, and text files are accepted, with a combined limit of 50 MB per project.

curl -X POST https://mirofish.my/api/mirofish/uploads/init \
  -H "Authorization: Bearer $MIROFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: upload-init-001" \
  -d '{
    "clientSubmissionId":"submission-001",
    "files":[{
      "fileId":"brief-1",
      "name":"market-brief.pdf",
      "size":123456,
      "contentType":"application/pdf",
      "sha256":"64-lowercase-or-uppercase-hex-characters"
    }]
  }'

PUT the exact bytes to each returned uploadUrl with the returned headers, then verify:

curl -X POST https://mirofish.my/api/mirofish/uploads/complete \
  -H "Authorization: Bearer $MIROFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: upload-complete-001" \
  -d '{"clientSubmissionId":"submission-001","uploadIds":["upload_..."]}'

For a publicly downloadable source, POST /api/mirofish/projects/import-url is a shortcut that follows the same project and quota path.

2. Create a project

curl -X POST https://mirofish.my/api/mirofish/projects \
  -H "Authorization: Bearer $MIROFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: project-001" \
  -d '{
    "prompt":"Simulate how the target market may react to this launch.",
    "clientSubmissionId":"submission-001",
    "uploadIds":["upload_..."]
  }'

Poll GET /api/mirofish/projects/{projectId} until the project reaches graph_ready or simulation_idle.

3. Read the graph

Once the graph is ready, retrieve the generated ontology and graph:

  • GET /api/mirofish/projects/{projectId}/ontology
  • GET /api/mirofish/graphs/{graphId}?projectId={projectId}

4. Start a simulation

curl -X POST https://mirofish.my/api/mirofish/simulations/{simulationId}/start \
  -H "Authorization: Bearer $MIROFISH_API_KEY" \
  -H "Idempotency-Key: simulation-start-001"

The first accepted start charges the account once. Repeating the same start is idempotent. Poll GET /api/mirofish/simulations/{simulationId} for status and progress. Intermediate product signals are available from the profiles, actions, posts, timeline, comments, and agent-stats endpoints in the reference.

5. Generate a report

curl -X POST https://mirofish.my/api/mirofish/reports/{reportId} \
  -H "Authorization: Bearer $MIROFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: report-generate-001" \
  -d '{"forceRegenerate":false}'

Read the report, sections, and sanitized agent log while it is generated. After completion, POST /api/mirofish/reports/{reportId}/chat supports the same report-agent and world-character modes as the web application.

Webhooks

Register an HTTPS endpoint for project.graph_ready, simulation.completed, or report.completed. The signing secret is returned once. Verify v1 as HMAC-SHA256 of <timestamp>.<raw-request-body>, reject old timestamps, and deduplicate with X-MiroFish-Event-Id.

curl -X POST https://mirofish.my/api/mirofish/webhooks \
  -H "Authorization: Bearer $MIROFISH_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: webhook-endpoint-001" \
  -d '{
    "url":"https://api.example.com/webhooks/mirofish",
    "events":["project.graph_ready","simulation.completed","report.completed"]
  }'

JavaScript

const apiKey = process.env.MIROFISH_API_KEY;
const response = await fetch("https://mirofish.my/api/mirofish/projects/PROJECT_ID", {
  headers: { Authorization: `Bearer ${apiKey}` },
});
if (!response.ok) throw new Error(await response.text());
const { project } = await response.json();
console.log(project.status);

Python

import os
import requests

response = requests.get(
    "https://mirofish.my/api/mirofish/projects/PROJECT_ID",
    headers={"Authorization": f"Bearer {os.environ['MIROFISH_API_KEY']}"},
    timeout=30,
)
response.raise_for_status()
print(response.json()["project"]["status"])

Errors and retries

Use the HTTP status and the response body's error_code to decide whether to retry. Retry transient 5xx responses with backoff and the same idempotency key. A 402 API_INSUFFICIENT_CREDITS response includes the required credits, current balance, and top-up URL. Never retry a request with a new idempotency key unless you intend to create a new operation.

Machine-readable contract: the complete OpenAPI 3.1 document is available as openapi.yaml and rendered in the API Reference.
